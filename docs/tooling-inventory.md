# Tooling cleanup inventory

This records the pre-change audit of all **88 tracked files under `scripts/`** at
`83d5376`. Each file was inspected for callers and the invariant it protects before
moves or deletions. Destinations describe the cleanup, not new curriculum authorship.
Current commands and directory ownership are documented in [tooling.md](tooling.md).

## Decisions that require context

The two publication compatibility suites and their baselines are consolidated into
one test and one captured fixture. Existing deployed hashes and provenance are
copied unchanged; expected hashes are not regenerated. The build's exact grading
version alias is retained separately because persisted offline submissions depend
on it. General validator tests cannot replace these identity and contract checks.

The deleted linear-algebra core seed did not check historical IDs and was weaker
than the complete published-contract snapshot plus the two retained split-pacing
fixtures. The deleted inline reporter embedded obsolete counts and fails on
reading-only introductions. The deleted Review comparator reproduced one completed
rollout from untracked baseline captures; its historical report and CSV remain.
Current Go review identity, effective-catalog, activation, restore, and browser
checks retain the ongoing contracts. They do not impose permanent byte equality
on every historical Review definition.

Both Python verification utilities remain independent of TS/Go grading. The
adversarial utility constructs mathematical oracles; TS and Go execute production
graders against the materialized cases. The SymPy utility verifies exercise-linked
arithmetic and prompt/answer freshness. Its existing `linear-algebra-vectors/23`
prompt mismatch is reported separately; this cleanup does not change canonical
content to silence it. The exporter remains a standalone user utility, with its
Python regression test under `tests/utilities/`.

## Related files outside the original scripts inventory

All **20 test-only JSON files from `shared/`** move to
`tests/grading/fixtures/`, with both TS and Go test readers updated. Runtime grader
and contract code remains in `shared/`. The adversarial corpus changes only its
generator-location description; case definitions and expected outcomes stay intact.
The exercise-linked numerical verification data under
`content/linear-algebra-verification.json` remains canonical declarative data.

Three existing browser checks from `web/tests/` join the same E2E area:
`draftHydration.browser.mjs` → `e2e/draft-hydration.spec.mjs`,
`structuredAnswer.browser.mjs` → `e2e/structured-answer.spec.mjs`, and
`retryGrading.browser.mjs` → `e2e/retry-grading.spec.mjs`.
Straightforward checks become TypeScript; larger working MJS checks retain their
language. They share an explicit runner and local browser/server setup, with
artifacts under ignored `output/e2e/`.

Ignored `scripts/__pycache__/` files are generated Python bytecode, not part of the
88 tracked source files. Removing that local cache is housekeeping, not deletion
of a test, fixture, or compatibility guarantee.
